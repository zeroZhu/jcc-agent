# 需求与完成证据

## 用户要求

1. 以画之灵为例，根据当前局势和来牌选择适合的阵容。
2. 余牌只需粗估，使用对手棋盘与备战席最近的观察快照。
3. 在回合/对战间隙轮询对手；通过点击棋子详情读取文字。
4. 运行时仅使用 PaddleOCR，不接入英雄外观分类或视觉大模型。
5. 自动按目标阵容买牌、D 牌；刷新周期以 1–2 秒为目标，不盲目按定时器点击。
6. 用用户给出的游戏录像验证：00:00–00:23 开局奇遇；00:24–00:30 过渡；00:31–02:12 野怪；02:13–02:28 第一次强化选择；02:29 后续对局；04:20 后包含棋子详情。
7. 不确定事项保存为 Markdown，包括问题、选项、推荐默认方案和验证状态。
8. 完成可运行 Agent 与开发文档，记录实测及尚不能证明的边界。

## 完成验收

- 可安装的 Python 项目、命令行入口、配置和中文使用说明。
- 真实录像提帧、OCR 输出、独立阶段标签对比和代表性详情识别证据。
- 阶段识别不得仅按录像时间回填；录制者原有点击不得计为 Agent 操作成功。
- 英雄名必须落在版本英雄表；空位和未知分离；星级不可读时保留区间。
- 快照更新不得重复累加；过期与缺失数据必须显式展示。
- 阵容选择与转型、目标数量、预算、购买预留金及停止条件可复现。
- 操作版本校验、确认、超时恢复、人工停止和侦察互斥有行为测试。
- 实际运行数据与合成测试分开汇报；直播点击验证未完成前不得宣称全流程实战验证。

## 证据位置

开发过程生成的素材、日志和报告在 `artifacts/`，该目录不入版本控制。最终验收结果记入 `docs/validation.md`。
