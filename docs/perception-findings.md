# 录屏与纯 OCR 验证

本文区分录屏人工标注、OCR 实际输出和待确认问题。运行时不使用英雄图片分类、视觉大模型，也不会以录像时间推断游戏阶段。

## 实现与复现

- `src/jcc_agent/perception.py`：PaddleOCR 3.x 懒加载适配器、normalized ROI、文本到结构化状态的转换。
- 默认显式选择 `PP-OCRv5_mobile_det` 和 `PP-OCRv5_mobile_rec`，关闭文档旋转、透视校正和文字方向模型；固定横屏游戏画面无需这些处理。
- `full_frame` 模式每帧 OCR 一次，再按区域筛选文字；`mosaic` 模式先裁剪放大区域，拼接为带间隔的画布，再 OCR 一次。裁剪、缩放、文字框位置筛选属于文字识别预处理，不承担英雄外观识别。
- 当前默认 `recognition` 模式用 `PaddleOCR.TextRecognition` 批量读取已标定的单行区域，跳过文字检测。英雄姓名、实际售价、金币、等级、经验、回合、倒计时、详情名和选项标题分区读取。该模式只读取选择标题；需要完整说明时改用 `mosaic`/`full_frame`。仅对单行区域适用，不能直接套到完整卡片或多行说明。
- 开启 oneDNN (`enable_mkldnn=True`)，CPU 线程数为 4。该开关已在当前 Windows / PaddlePaddle 3.3.1 上实际验证；若别的安装环境不兼容，可显式关闭，但性能会明显降低。
- `OCRReader(engine=...)` 可注入假引擎，用于验证解析与控制边界。假引擎测试不算真实录屏识别准确率。
- `src/jcc_agent/video.py` 用 OpenCV 读取视频信息、按时间抽帧。输出的 `reference_phase` 是用户标注，明确带有 `reference_source=user_annotation_not_prediction`。
- 对 PaddleOCR 3.x 返回的 `rec_texts` / `rec_scores` / `rec_polys` 做逐项对齐；未知结构直接报错，不生成伪造的识别结果。[PaddleOCR 官方接口说明](https://www.paddleocr.ai/latest/en/version3.x/pipeline_usage/OCR.html)

## 感知约束

1. 商店名称只做当前赛季英雄名/别名的精确匹配。低置信、未匹配、多英雄冲突均为 `unknown`；不采用可能买错牌的强制模糊匹配。
2. 没有识别到文字不等于空格。只有配置了可信的空位文字证据才能输出 `empty`，当前游戏界面不预设有这种证据。
3. 详情中的英雄姓名可确立身份。星级只接受明确的数字/中文星级文本；星星图标不会强行转成副本数量。
4. 关闭详情必须有独立的正面证据。可配置被详情遮住的背景文字区域，但必须先在实际界面验证遮挡关系。没有英雄名不等于面板已关闭。
5. 观看玩家必须从真正表示“当前被观看者”的区域读取。排行榜中始终存在的自己的姓名不能证明已经返回自己棋盘。
6. 游戏阶段来自阶段区域的文字；野怪回合表只是版本规则配置。录像时间和参考标签不进入感知模块。

### 录像暴露出的实际限制

- 金币在右下，经验/等级在左下；自己血量不能从排行榜某个固定排名行取，因为排名会变化。示例暂不配置血量 ROI。
- 画面上小小英雄的姓名会移动，不能把某固定区域或排行榜上的自己名字等同于“正在看自己棋盘”。运行配置需要 `regions.viewed_player`、`self_player_name` 与 `player_name_map`（玩家 ID 到显示姓名的映射）共同标定。
- 战斗中也能打开商店。商店可见不能作为准备阶段的判定条件。没有阶段文字的孤立帧应输出 unknown；后续若加入连续流阶段跟踪，也必须以实际检测事件为依据。
- 星级图标、棋盘占位、空格状态在本素材中没有通用、稳定的文字证据。未知星级供牌库模块输出范围，空格未知会限制自动安排棋子与满备战席操作，不能在报告中宣称已经全自动解决。
- 已找到并实测更稳定的关闭证据：右侧详情会遮住商店的「刷新」文字。独立 ROI 精确读取「刷新」且没有详情英雄冲突时，标记 `detail_open=False`、`shop_visible=True`。另一个候选证据是本局排行榜姓名「熟了个饭」；该姓名仅适用本局，后续必须更新。没有这些文字不代表面板开启/商店隐藏，仍为 unknown。
- 当前纯 OCR 模块从不输出 `shop_visible=False`。真实隐藏、面板遮挡、文字漏读均可能没有「刷新」，不能据此区分。若自动打开商店的控制条件要求明确 False，默认感知路径尚不能提供该证据；需要其它已验证状态来源，不能把 None 自动改为 False。
- 商店的观察售价独立于 `Hero.cost`：前者进入 `SlotObservation.cost`，后者仍表示牌池费用档位。若价格读取失败，观察售价为 None，执行器不能按档位猜价。

## 真实 PaddleOCR 验证结果

最终环境版本：Python 3.13.6、PaddleOCR 3.4.1、PaddlePaddle 3.3.1、`opencv-contrib-python` 4.10.0.84。已移除重复安装的 `opencv-python`，依赖检查通过，并在整理后的环境重新跑完下表基准。官方模型下载先尝试 aistudio 返回 404，随后 PaddleX 自动从 ModelScope 的 `PaddlePaddle/PP-OCRv5_mobile_det` 与 `PaddlePaddle/PP-OCRv5_mobile_rec` 仓库成功下载，缓存于用户 `.paddlex/official_models`。未使用测试替身生成以下结果。

最终基准使用 12 个已人工审阅的独立帧、每帧重复两遍，包含 27 秒转场；准确率只统计独立帧，重复用于延迟采样。人工真值保存于 `validation/example_video_ground_truth.json`；模型推理不读取真值。实际结果文件位于 `artifacts/perception/environment-final/`。

|---|---|---|

| 整组商店姓名 | 4 / 4 正确 | 空白卡槽保留 unknown，不计作“已识别空位” |

### 为什么改用单行批量识别

早期关闭 oneDNN 的“全图检测 + 识别”基线热态 P50 19.205 秒、P95 29.083 秒；区域拼图基线 P50 13.770 秒、P95 18.370 秒。两者英雄名都能读取，但小售价数字经常没有检测框。

之后同时进行了三项有实测依据的改进：裁出单行并直接文字识别、修正各卡片价格框偏移、开启 oneDNN。在相同的初步单行布局上，单独对比 oneDNN 开关：开启后七次热态耗时 0.420–0.478 秒，关闭后约 3.936–5.803 秒。加入更多必要字段和关闭证据后，最终采用上表完整配置的 0.859 / 0.943 秒，不拿较小布局的 0.4 秒冒充最终方案性能。

保留的中间基准：整理 OpenCV 依赖之前（OpenCV 4.14.0.94），11 个独立帧的商店姓名与售价均 19/19、详情 3/3；热态 P50 / P95 为 0.806 / 0.920 秒，最大 1.092 秒，缓存模型首次调用 4.768 秒。这套结果保留于 `artifacts/perception/final_validation/` 作为演化历史，不作为当前环境的最终数字。

### 复现命令和产物

```powershell
$env:PADDLE_PDX_DISABLE_MODEL_SOURCE_CHECK = 'True'
.venv/Scripts/python.exe scripts/validate_recording.py --video '示例视频.mp4' --out artifacts/perception/new_validation
```

默认使用当前 `configs/layout.example.json`、独立人工真值与 `recognition` 模式；支持 `--modes recognition,full_frame,mosaic`、`--no-mkldnn`、`--repeats`。输出目录不能已含观测日志，以免混入旧记录。若权重尚未下载，关闭连接预检查也不会禁止正常下载。

- `artifacts/perception/environment-final/summary.json`：当前最终环境版本、视频指纹、12 帧统计及验证范围。
- `artifacts/perception/environment-final/observations.jsonl`：每次真实 OCR token、置信度、结构化状态和耗时。
- `artifacts/perception/environment-final/layout_used.json`、`truth_used.json`：该次基准使用的配置与人工真值快照。
- `artifacts/perception/final_validation/`：此前 OpenCV 4.14.0.94 环境的 11 帧基准及快照，保留供比较。
- `artifacts/perception/ocr_validation.json`、`baseline_summary.json`：早期全图/拼图输出和统计。
- `artifacts/perception/ocr_optimization.json`：同一初步单行配置 oneDNN 开关对比。

仍未验证：实际窗口点击是否准确生效、当前被观看玩家的可靠识别、逐格扫描与空位判定、星级文本以外的替代证据、完整购买/刷新闭环端到端耗时。这些是明确的后续验证项；不把离线帧识别成功当作实战自动操作验收。

转场覆盖说明：27 秒帧是暗场淡出，没有可读的转场标签。主 CLI 的 12 帧验收记录在 `artifacts/cli-validation/`，该帧预测为 unknown，符合不按时间硬编码阶段的约束。它已包含在当前最终环境的 12 帧基准中；旧 11 帧基准保留原统计，未修改旧分母。
